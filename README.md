# RF-монитор: Orange Pi Zero 3 + SA6 + RODOS

Веб-приложение: управляет тремя реле RODOS (каналы генератора T3) и по измерениям SA6 показывает,
обнаружен ли каждый сигнал. Реле и результат измерения отображаются раздельно.

## Модули (`app/`)
| Файл | Роль |
|---|---|
| `rodos.py` | реле по HTTP, чтение состояния (`pstat.xml`) без кэша, `all_off` |
| `sa6.py` | протокол Arinst `scn20`: скан, разбор и проверка ответа |
| `calibration.py` | полный скан 100-2000 МГц, поиск трёх пиков, сохранение пресета |
| `monitor.py` | фоновый поток: узкие окна вокруг частот из пресета, статусы |
| `storage.py` | `preset.json`, `state.json` (отдельно от пресета), журнал SQLite |
| `main.py` | API и запуск потоков; `static/index.html` - интерфейс |

## Установка на Orange Pi
```bash
scp -r monitor-sa6-arinst orangepi@<IP>:~ && ssh orangepi@<IP>
cd ~/monitor-sa6-arinst && sudo bash deploy/install.sh      # venv, сервис, автозапуск, NTP
```
Интерфейс: `http://<IP платы>:8000`. Настройки (порт SA6, IP RODOS) - переменные `SA6_PORT`, `RODOS_IP`,
`RODOS_USER`, `RODOS_PASSWORD`, `RF_DATA_DIR` в `/etc/systemd/system/rf-monitor.service`. Логи: `journalctl -u rf-monitor -f`.

## Как работает
- **Старт:** на реле 1-3 отправляется OFF (если RODOS недоступен, повторяется, пока не пройдёт). Автовключения нет.
- **Реле:** состояние читается с устройства при каждом запросе статуса; при сбое - "неизвестно". Если связь пропала в работе, один раз пробуем OFF.
- **Калибровка**: включить три канала, 5 широких сканов 100-2000 МГц
  (куски по 256 точек, шаг 1 МГц) с накоплением максимума; фон = скользящая медиана (31 точка), пик = локальный максимум на 10+ дБ
  выше фона, берутся три сильнейших, частота = старт + i*шаг. Пики нумеруются по возрастанию частоты; затем реле выключаются.
  Частоты 423/433/443 в алгоритме не используются.
- **Мониторинг:** T3 излучает каналы по очереди, поэтому за цикл (2 с) окна всех трёх сигналов (±3 МГц) сканируются по кругу.
  Порог канала = превышение над фоном при калибровке минус допуск `tolerance_db` (15 дБ), но не ниже `threshold_db` (10 дБ);
  пик учитывается только в пределах `freq_tol_hz` (1 МГц) от сохранённой частоты. "Обнаружен", если порог превышен минимум в `confirm` (2) сканах;
  ошибка SA6 -> "ошибка измерения". В карточке канала показано "+X дБ над фоном (нужно Y)".
- **Каналы и пики:** пики нумеруются по возрастанию частоты (как реле 1 < 2 < 3 в ТЗ).
